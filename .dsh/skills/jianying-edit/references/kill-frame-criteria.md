# 击杀帧的判定：判据、标定与「帧」能精确到哪一步（2026-09-14 第 7 轮）

本文件是 `kill-extraction.md` 的**续篇**，但结论不同层：

| 文件 | 回答什么 |
|---|---|
| `kill-extraction.md` | **横幅在哪**（坐标标定）、旧标定为什么错、共现判据在成片上为什么退化成切点探测器 |

## 3. 「锚点 → 击杀帧」的换算（本轮实测，**结论是「只在一例上成立」**）

实测（6.533s 那一例，逐帧洋红占比）：

| 帧 | 相对突变帧 | 洋红占比 | 含义 |
|---|---|---|---|
| 195 | b−1 | 0.000 | 特效尚未出现 |
| **196** | **b（锚点）** | 0.000 | **HUD 帧间差最大的一帧**（Δ=5.80） |
| 197 | b+1 | 0.157 | 洋红特效首现 |
| 198 | b+2 | 0.803 | 铺满 |
| 205 | b+9 | 0.083 | 退场 |

**但把同一条带（y30~80 / x420~860）跑遍全部 10 个锚点，只有 6.533s 这一例有信号：**

| 锚点 | b+1 洋红 | 窗口峰值 | 首现帧 |
|---|---|---|---|
| **196** | **0.167** | **0.803** | **197** |
| 322 / 351 / 419 / 428 / 479 / 639 / 682 / 757 / 765 | ≤0.005 | ≤0.005 | 无 |

> ⇒ **「锚点 + 1 帧 = 特效首现」只在 1/10 个锚点上成立**，不能当通用规则。
> 这也反过来证明：**那条洋红不是击杀横幅**（真横幅应该在每次击杀都出现）。
> 标记落点规则（`标记起点 = b − 1 帧`，持续 6 帧）因此**只是本项目策略（L4）**，
> 依据是「锚点是 HUD 相对上一帧发生变化的第一帧」，不是「横幅首现帧」。

## 4. 时间码的坑：30fps 下「帧」不是整数微秒

剪映存的是**整数微秒**，而 30fps 的 1 帧 = **33333.33µs**。
所以「帧 → 秒 → 微秒」两头取整会**系统性错位 ±33µs**：

```
F350 理想值 = 350/30 s = 11666666.67µs → 草稿里是 11666700µs
F418 理想值 = 418/30 s = 13933333.33µs → 草稿里是 13933300µs
```

本项目第一次跑独立校验时，就是拿「理想帧值」去比草稿的微秒整数，**报出 12 个假问题**。
治法：**只保留一份真值** —— 帧号 → 微秒整数（`round`），EDL 的秒值、台账、校验全部由它反推。

配套的读数口径：**反算帧号必须用 `round`，不能用 `int`**
（`13933300µs × 30 / 1e6 = 417.999`，`int()` 截断成 417，实际是 418）。

## 5. 本轮的判断边界（明确说清「没做到什么」）

- **10 个候选全部只有间接证据（`confidence` 一律 medium）**：本轮先误把「整屏洋红」当横幅、
  把其中一个标成 high，被子 agent 独立抽帧推翻后**全部降级**。
- **没有人工 ground truth**：没有一条候选是经过「人看着画面说这就是击杀」确认的。
- **没有证明「HUD 突变帧 = 击杀帧」**：只证明了「这条素材的 HUD 会在这些帧发生变化」。
- **播放卡模板与 HUD 突变两种锚点语义不同、相差 ≈0.40s**，本轮不下结论（见 §3.1）。
- **没有做 AI 补帧/超分**：素材 30fps，帧号直接取自解码帧序，未做任何插帧推断。
- **联网的成果有限**：YouTube / Reddit / Google / github / arxiv 全部超时，
  B站 搜索接口全程 `-412 request was banned`（`_bili.mjs search` 与 `yt-dlp bilisearch` 都挂），
  Firecrawl 只回标题+摘要 ⇒ 「剪辑师公认对齐哪一帧」这一问题本轮**没答上**。

## 5.1 ★ 必须人工完成的一步

本轮产出的是**候选帧 + 标记草稿**，不是确认过的 ground truth。
真正把它变成训练数据，需要人在剪映里打开 `击杀帧标记_b61cc53d` 草稿，逐条看：

- 标记罩住的那一帧**是不是**画面里的一次击杀？
- 若是，**真实击杀帧**比标记早/晚几帧？

把结论写回 `kills_groundtruth.json` 的每个 event（本轮**故意没有预留 `human_verdict` 字段**，
避免「字段在就算做了」的错觉）。
