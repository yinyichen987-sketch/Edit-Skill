## 0. 使用说明

- **规则 ID 命名遵循任务书约定**：`HOOK-` / `SEL-` / `CUT-` / `TRN-` / `CAP-` / `AUD-` / `EXP-`（任务书 t3 的 C 项原文）。
  `format-spec.md` / `episode-plan.md` 的追溯表里另有一组细粒度 ID（`HOOK-01..04`、`CUT-01..03` 等），两者的对应关系见 §8 附录 A。
- **级别（P0–P5）** 表示**违反后果的严重程度**，不是重要性排序：

  | 级别 | 含义 | 违反处理 |
  |---|---|---|
  | **P0** | 违反即**事实错误 / 无法交付** | 必须重做 |
  | **P1** | 违反会造成**可感知的质量事故** | 必须修改后再生效 |
  | **P2** | 违反会**削弱效果**但有补救 | 记录并说明 |
  | **P3** | 结构一致性要求（LS/VT 两版之间、EDL 与草稿之间） | 用脚本校验 |
  | **P4** | 需按平台/场景调整的偏好 | 可覆盖，需写理由 |
  | **P5** | 待实测确认的假设 | 不得当作已证结论引用 |

- **判定条件**一律写成**可在成片/EDL 上直接观察**的形式（"某字段是否满足某式"），不写"感觉太快/太闷"。
- **不写没有出处的规则**。每条规则的「来源」栏必须指向 t1 的实测或 t2 的结论；本规则集刻意**不含**「按播放量/涨粉效果」的经验总结——`[t2 §10]` 已声明这类数据无可引用来源。

## 1. HOOK —— 开场钩子

### HOOK-01 · 首帧必须是严格池里的动态画面
- **级别**：P0
- **判定条件**：`clip[0].role == "hook"`，且其素材区间 `[source_in, source_in+duration]` **完整覆盖** t1 **严格池**（4.3 s）的 5 个片段之一：`a[6.35,6.95]`、`a[11.60,12.20]`、`b[5.40,7.00]`、`b[8.50,9.10]`、`c[6.40,7.40]`；且首片段 `start == 0.0`。
  > **口径为「覆盖」而非「`source_in` 落在区间内」**（Plan B 后明确）：高光余量规则（CUT-05）要求高光前留 ≥0.3 s，因此 `source_in` **可以早于**严格池区间起点。本集即取 `a=6.05 < 6.35`，由该片段覆盖 `A-H3`。
- **反例**：用中置信段的音频瞬态当首帧（如 `c=10.40`、`c=19.10`）——画面事件在 t1 里未获视觉确认，首帧无法兑现字幕承诺。
- **来源**：`[t1 §5.1 严格池]` + `[t2 §3.1]` 结果前置。
- **落地**：✅ 本集合规 —— 首片段取 `a=6.05`（2 HP 交火，`A-H3` 置信 0.95），使严格池 `A-H3` 区间 6.35–6.95 前留 0.30 s（满足高光余量 ≥0.3 s），2 HP 读数在前 2 秒内即进入画面。

### HOOK-02 · 首帧同帧起声，禁止任何片头
- **级别**：P0
- **判定条件**：`clip[0]` 带音频（非静音轨），且**没有**任何 `duration ≥ 0.05 s` 的黑场/LOGO/纯色片段位于 0.0 s；音频没有 ≥0.1 s 的淡入；`texts` 里最早一条的 `start ≥ 0.0` 且首条字幕 `start ≤ 0.4`。
- **反例**：0.0–0.3 s 黑场 + LOGO；BGM 淡入 0.5 s；首帧是加载界面/地图界面/结算界面。
- **来源**：`[t2 §3.1 硬规则]`、`[t2 §7 反模式#2]`。
- **落地**：✅ 本集合规（首字幕 `start = 0.20`）。

### HOOK-03 · 首帧必须同时可用作抖音封面
- **级别**：P2
- **判定条件**：`clip[0]` 的入点画面满足：①画面中心有主体（敌方模型 / 准星 / 击杀特效）；②不含静态文字块；③不是结算/观战界面。
- **反例**：拿 `a∈[16.25,18.984]`（死亡回放卡片 + 灰底战况总览）当首帧 —— 无对战内容 `[t1 §5.4]`。
- **来源**：`[t2 §6]`（首帧即封面）。

### HOOK-04 · 结尾用提问式互动，禁止硬广 CTA
- **级别**：P1
- **判定条件**：最后 2.0 s 内**恰好一条** `role == "ending"` 的文本，内容为疑问句（以「？」结尾），字数 ≤ 12；文本中**不出现**「点赞」「关注」「三连」「求」「订阅」。
- **反例**：「记得点赞关注」「求个三连」`[t2 §7 反模式#9]`；或写下集预告（本轮只产 1 集，预告即为虚假承诺）。
- **来源**：`[t2 §3.4 提问式结尾]` + 项目最终裁决（单集爆量）。
- **角色定位**：本条只管"结尾必须是提问式互动、且不得是硬广"。本集 S4 取 b 段「获胜」横幅（`B-H7`，21.40–24.80）承载提问字幕 #5「这枪换你，敢不敢上？」（疑问句 / 11 字 / 12.30–14.80 s）。

## 2. SEL —— 素材选择

### SEL-01 · 只用 t1 已验证的片段，且分级使用
- **级别**：P0
- **判定条件**：每个 `clip.source` 与 `(source_in, source_in+duration)` 区间必须能在 `material-analysis.json` 的 `highlights[]` 里找到覆盖它的条目。分级用法：

  | 信任级 | 允许的 `role` |
  |---|---|
  | 严格池（`confidence ≥ 0.75` 且有画面确证） | `hook` / `body` / `ending` |
  | 中置信战斗（`confidence 0.5–0.7`，仅音频确证） | 仅 `body`（过程段） |
  | 情绪节拍（`B-H7` 获胜横幅等 UI 定格） | 仅 `ending` |

- **反例**：用 `a∈[0.00,0.50]`（t1 未列为高光）做开场；把 `B-H7` 的界面当正文使用（`[t1]` 明确"界面本身不可当作正文"）。
- **来源**：`[t1 §5.1/5.2/5.3]`。
- **落地**：✅ S1 = 严格池（`A-H3`）；S2 = 严格池 + 中置信（`A-H4`/`A-H5`）；S3 = 严格池 + 中置信（`B-H1`/`B-H2`/`B-H3` 前段）；S4 = 中置信动态段（`A-H6`，**其上的字幕不含任何事件断言**）。全集 4 个片段中 3 个含严格池内容。

### SEL-02 · 禁止用重复画面区间灌时长
- **级别**：P0
- **判定条件**：**按 `(source, source_in, duration)` 三元组**判定 —— 任意两条片段的三元组不得相同；同 `source` 的区间不得二次出现。**不要按时间线区间判定**：相邻片段在时间线上首尾相接（0.00–2.00 / 2.13–6.13）是同一段连续镜头的自然接续，不是复现。
- **反例**：把 `b∈[5.40,7.00]` 播两遍凑到 15 s（`[t2 §7 反模式#5]`：素材不够的最快掉粉做法）。
- **来源**：`[t2 §7 反模式#5]` + 任务书硬约束。
- **落地**：✅ 本集 4 个片段三元组互不相同，同源区间两两不交叠（a：6.05–8.10 / 8.10–12.50 连续；b：5.00–10.60 与 21.40–24.35，中间留 10.80s 空隙）。**无任何复用**，故无需例外登记。

### SEL-03 · 不得假设跨段"同一回合连续"
- **级别**：P0
- **判定条件**：字幕/标题文案中不出现「接着」「上一枪之后」「本回合」「刚才」这类**声称时间连续性**的词；也不出现具体比分数字（三段比分 8–3 / 0–0 / 4–2 互不相容）。
- **反例**：「上一枪刚打完，他继续推进」——三段来自不同回合 `[t1 §3]`。
- **来源**：`[t1 §3]`、`[t1 §8-5]`。

### SEL-04 · 涉及"谁杀的/杀了几个"的表述必须收窄到画面可证
- **级别**：P0
- **判定条件**：字幕中若出现「击杀 / 三杀 / 双杀 / 我」这类归属词，必须在 `material-analysis.json` 中有**对应条目归属**的证据（`type == "kill_confirmed"` 或带明确昵称的 `kill_team`）。
  允许的收窄写法：`A-H5`/`B-H5` 可写「团队击杀」「播报三条」；`B-H2`（`我 ⟨枪⟩ ZCQ891`）、`C-H5`（`我 ⟨Vandal⟩ 分别各奔东西`）可写「击杀」。
- **反例**：把 `A-H5` 的两条播报写成「我拿了双杀」——`[t1 U5]` 明确"哪条属本地玩家不明确"。
- **来源**：`[t1 U5]`、`[t1 §5.1]`。

### SEL-05 · 未确证的实体不得上屏
- **级别**：P0
- **判定条件**：`texts[].content` 中不出现英雄（agent）名称；不出现未经图像比对确证的地图名。
- **反例**：「用捷风一穿二」——`[t1 U4]` 明确玩家英雄未确证。地图 Lotus 置信仅 0.75 `[t1 U3]`，也不上屏。
- **来源**：`[t1 U3/U4]`。

## 3. CUT —— 结构与切点

### CUT-01 · 固定四段结构，总长 15.0 s（±0.2）
- **级别**：P1
- **判定条件**：`end = start(last) + duration(last)` 落在 `[14.8, 15.2]`；四段语义齐全（S1 钩子 / S2 建立 / S3 高潮 / S4 收束），各段净时长占比**接近** 2 : 4 : 7 : 2。
- **反例**：把总长做到 12 s（丢掉完播率的时长优势）或 19 s（`[t2 §3]` 的结构是 15 秒口径）。
- **来源**：`[t2 §3.3]` + 项目约束（15 秒）。
- **落地**：✅ 本集 `end = 15.00`，配比 2.05 : 4.40 : 5.60 : 2.95（S3 略短于建议值，因素材里唯一能撑住高潮的连续区间必须在 `b` 段不安全窗口 [10.9797, 11.0454] 之前收尾）。

### CUT-02 · 单片段 0.5–6.5 s，切换点密度 ≈ 12 切/分
- **级别**：P2
- **判定条件**：每条 `clip.duration ∈ [0.5, 6.5]`；`(片段数−1) / 总时长 × 60 ∈ [10, 16]`。
- **反例**：把 `B-H3` 的 3.4 s 拉成 7 s 单片段（超过 6.5 s，画面动作会衰减）；或切出 0.2 s 的碎片（手机端来不及读，信息带宽浪费）。
- **来源**：`[t1]` 最长连续可用段 3.4 s、中位 1.0 s（决定了片段预算的上下界）；`[t2 §3.2]` 每 3 秒一个信息点。
- **落地**：✅ 4 片段（2.05 / 4.40 / 5.60 / 2.95 s，均在区间内），3 切 / 15 s = **12 切/分**。

### CUT-03 · 本集的 LS 与 VT 必须共用同一份 clip 时间线
- **级别**：P3（**必须用脚本判定，不能靠肉眼**）
- **判定条件**：`projects/game-001/edl/ep01.json` 与 `ep01-vertical.json` 的 `clips` 数组**逐字段相等**（`source` / `source_in` / `start` / `duration` / `role` / `rule_id` / `reason` / `volume` / `speed` / `transition`）；只允许 `canvas` 与 `texts` 不同（文本因画布而位置/字号不同）。
- **反例**：为了竖屏"更好看"而在 VT 版里删掉一段或改一个入点——两版就变成了两条片子，违背"同一个剪辑"的要求。
- **来源**：captain 最终裁决（两版都做）；`format-spec.md §7.1`。

### CUT-04 · 片段时间码不得越过素材 Video 流上界
- **级别**：P0
- **判定条件**：`source_in + duration ≤` 上界，且**留 ≥ 1 帧（0.034 s）余量**：`a ≤ 18.984`、`b ≤ 26.017`、`c ≤ 25.012`。由 `edl_to_draft.py --dry-run` 的越界校验兜底（容差 0.001 s）。
- **反例**：拿容器时长卡点（`a` 取到 19.03）——剪映里末帧取不到画面，表现为黑尾/末帧滞留。
- **来源**：`[M]` MediaInfo Video 轨 duration（`format-spec.md §2.2`）。
- **落地**：✅ 本集四段余量 **10.884 / 6.484 / 15.417 / 1.667 s**（Plan B 后；最小 1.667 s ≫ 1 帧）。由 `projects/game-001/tools/verify_cut_margins.py` 判定 → `RESULT: ALL PASS`。
- **与 CUT-05 的区别**：本条防的是"切到素材尽头取不到画面"；CUT-05 防的是"切点落在 VFR 丢帧/视点跳变处导致并轨漂移"。**两条都要满足**。

### CUT-05 · 切点容差 ±0.1 s、高光前后留 ≥0.3 s、优先从真实视点跳变之后切入
- **级别**：P1
- **判定条件**（三条同时成立）：
  1. 每个片段的 `source_in` 与 `source_in + duration` 距**任何已知丢帧点或真实视点跳变点** ≥ **0.1 s**；
     已知窗口（**真实 PTS 区间，不是点**）：`b [10.9797, 11.0454]`（已把该段 VFR 丢帧吸收在内）、`b [12.9787, 13.0120]`、`c [2.0717, 2.1050]`、`c [3.3717, 3.4050]`；`a` 为空（CFR）。**名义帧号换算对 VFR 素材系统性偏早，不得用点、也不得用帧号算术。**
  2. 每个高光事件的入点前后各留 **≥0.3 s** 余量（不贴边切）。
  3. 若必须紧邻一个真实视点跳变，**只能取"跳变之后"的一侧**。
- **反例**：把 `b` 段高潮段尾取在 `11.00` —— 距跳变 `0.000 s`、距丢帧 `0.020 s`，切口落在视点跳变/丢帧处，剪映并轨时可能漂移甚至露出跳变帧。（**这正是本规则诞生时抓到的真实缺陷**：v2 方案就是这么写的，已改。）
- **来源**：`[t1]` 复核（b/c 为 VFR、各有 1 处丢帧、时间码分辨率 0.25 s）+ creative-reviewer 的 `showinfo` 逐帧 PTS 与像素级跳变实测。**跳变清单是下界**，故本条按"未知点也留容差"的保守口径执行。
- **落地**：✅ 本集区间为 a 6.05–8.10、a 8.10–12.50、b 5.00–**10.60**、b 21.40–24.35；b 段出点距窗口 [10.9797, 11.0454] 起点 **0.380s**；b 段入点 21.40 落在窗口 [12.9787, 13.0120]**之后** 8.388s。**高光前后余量最小的三处恰为 0.30 s**（c1 入、c2 入、c2 出），其余更大；**违规 0 处**。 脚本 `projects/game-001/tools/verify_cut_margins.py` 逐点复算。
- **交付要求**：本条含一项**必须随交付给人工**的已知限制 —— "需要逐帧精确的片段应在剪映里目视微调，而不是按时间码硬切"（详见 `format-spec.md §12`）。

## 4. TRN —— 转场

### TRN-01 · 只允许硬切与 0.13 s 闪白；禁止一切柔和转场
- **级别**：P1
- **判定条件**：每个非首片段的 `transition.type ∈ {"闪白"}` 且 `duration == 0.13`（或省略 `transition` = 硬切）。转场名必须存在于 `pyJianYingDraft.TransitionType` 枚举（本机 451 个中文成员），否则 `--dry-run` 会报错。
- **反例**：叠化 / 模糊 / 黑场淡入淡出 / 闪黑 —— `[t2 §7 反模式#4]` 明确"禁用叠化、模糊等柔和转场"，会破坏射击游戏的利落感。
- **来源**：`[t2 §7 反模式#4]`（转场禁忌）。
- **落地**：✅ 本集 3 个转场全部为 `闪白` / `0.13s`（草稿 `materials.transitions` 实测已写入 3 条、duration=130000μs）。

### TRN-02 · 转场是**重叠**，不占额外总长
- **级别**：P0
- **判定条件**：`start(n) = start(n−1) + duration(n−1)`（**相邻片段零间隙**）；因此 `end = Σ duration`（转场不额外占时）。
  逆命题同样成立且更易自检：**如果 `Σ duration < end`，那么片段之间一定有空洞** → 那 0.1s 级空洞在时间线上**无素材**，剪映里表现为闪黑，违反 `qa.required` 的 `no-black-frame`。
- **反例（**我实际踩过的坑**）**：曾按"转场额外占时"建模，写出 `start(2)=2.13 / start(3)=6.26 / start(4)=12.39`（每处留 0.13s），结果是**每处转场都有一个 0.13s 的无素材黑洞**，全片 0.39s 闪黑；同时 `Σ duration 14.61 ≠ end 15.00`，公式自相矛盾。改为零间隙后 `Σ duration = 15.00 = end`，公式闭合、无黑洞。
- **来源**：`[environment.md]` 转场存储在片段上 + `edl_to_draft.py` 的实际排布语义（`add_transition` 挂到**同轨道前序片段**，转场区间取前序片段末 duration，两侧素材都在场）+ `[SKILL.md]` 第一优先级「不输出黑帧」。
- **落地**：✅ 本集 `start` 递进 0.00 → 2.05 → 6.45 → 12.05，三处间隙均为 0.000s；`Σ duration = 15.000 = end`。脚本 `tools/verify_cut_margins.py` 对间隙与总长同时校验。

### TRN-03 · 首个片段不得带转场
- **级别**：P2
- **判定条件**：`clip[0]` 无 `transition` 字段。转场语义为「进入本片段」，首片段无同轨道前序片段，写了会被工具忽略并告警。
- **来源**：`[edl-schema.md 转场语义]`。

## 5. CAP —— 字幕与包装

### CAP-01 · 中部游戏画面区零压字
- **级别**：P0
- **判定条件**：
  - VT（1080x1920）：所有 `texts` 的 `y ∈ [0, 656) ∪ (1264, 1620]`，**没有任何文本落在 656–1264**。
  - LS（1920x1080）：所有 `texts` 的 `y ≥ 900`（底缘安全带），**没有任何文本落在 700–900** 的准星/交火核心区。
- **反例**：在竖屏中部压大字标题（`[t2 §7 反模式#3]`）；把关键词字幕放在 LS 的画面正中。
- **来源**：`[t2 §4.1]`（游戏画面信息满屏分布，中部压字遮准星和敌人）。

### CAP-02 · 字幕 5±1 条、每屏 ≤2 行、每行 ≤12 字
- **级别**：P1
- **判定条件**：`len(texts) ∈ [4, 6]`；每条 `content` 的行数 ≤ 2、单行字符数 ≤ 12。
- **反例**：逐句转录游戏内语音（15 秒读不完）`[t2 §4.3]`；只放 1 条字幕（信息带宽浪费）；放 9 条（每条 <1.5 s，来不及读）。
- **来源**：`[t2 §4.3]` + `[t2 §3.2]` 每 3 秒一个信息点。

### CAP-03 · 每条字幕卡片 ≥1.2 s
- **级别**：P2
- **判定条件**：`texts[].duration ≥ 1.2`。
- **反例**：0.6 s 的字幕 —— 手机上读不完就消失，等于没上。
- **来源**：`[t2 §4.3]`（信息压缩要求）+ 移动端可读性的工程下限。

### CAP-04 · 字幕承担定位/解释/放大三职能，且有信息点节奏
- **级别**：P2
- **判定条件**：`texts` 的 `start` 序列中，相邻卡片间隔 ≤ 3.5 s；且存在至少一条承担"定位"职能的卡片落在 `[0.0, 2.0]`。
- **反例**：整片只有开场一句字幕，中段无任何信息补充（违反"每 3 秒一个信息点"）。
- **来源**：`[t2 §4.3]` 三职能表 + `[t2 §3.2]`。
- **落地**：✅ 本集 5 条卡片的 `start` 为 0.20 / 2.35 / 4.90 / 6.80 / 12.10，**相邻起始间隔最大 5.30 s**（超过 CAP-04 的 3.5 s，已登记取舍）；最大空白 2.50 s；承担"定位"职能的 #1 落在 [0.0, 2.05] 内。

### CAP-05 · 字号只给量级，不给"手机 1 秒可读"的量化承诺
- **级别**：P5
- **判定条件**：字号取值落在量级区间（VT/LS 的标题与提问 72 px、过程字幕 56 px，`@1080` 宽口径）；**不得**在文档或交付说明里声称"已满足手机 1 秒可读"。
- **反例**：写「字号 48px = 手机 1 秒可读」——`[t2 §4.2]` 明确未找到权威平台规范，唯一验收标准是人工手机预览。
- **来源**：`[t2 §4.2]`。

## 6. AUD —— 音频

### AUD-01 · 逐源响度对齐（相邻段残差 ≤0.4 LU）
- **级别**：P1
- **判定条件**：`clip.volume` 按源素材设置（算法 `10^((−16.0 − 源响度)/20)`，目标 −16.0 LUFS）：`a=0.700`、`b=0.851`、`c=0.912`；对齐后**相邻两段**的等效响度差 ≤ 0.4 LU（本规格实测 ≤ 0.003 LU）。
- **反例**：全片统一 `volume=1.0` —— 三段源相差 2.3 LU `[t1]`，接缝会响度跳变。
- **来源**：`[t1 §3/§8-7]` 三段响度 −12.9/−14.6/−15.2 不一致，需对齐。
- **落地**：⚠️ 本集只用 `a`、`b` 两段，所以实际只出现 **0.700 / 0.851** 两个系数；`c=0.912` 是规则备用的第三个值（`c` 段整段未使用）。接缝处只有 a→b 一处，残差 ≈ 0.001 LU。

### AUD-02 · 纯原声：禁 BGM、禁解说、禁重度压缩
- **级别**：P0（无 BGM/解说）/ P2（动态）
- **判定条件**：`tracks` 中不存在用于 BGM 的音频轨；`audio.bgm_volume` 不启用；不施加把 LRA 压到 <3 LU 的压缩。
- **反例**：加 BGM 垫底噪（会盖掉枪声/脚步信息，削弱原创性信号）`[t2 §5.3]`、`[t2 §7 反模式#8]`；把动态压平（枪声对比消失，片子变闷）`[t2 §5.2]`。
- **来源**：`[t2 §5.2/5.3]`。

### AUD-03 · 限幅是人工步骤，不得声称已完成
- **级别**：P0（**诚实性规则**）
- **判定条件**：交付说明中必须明确写出「限幅（ceiling −1.0 dBTP）需人工在导出前施加」，且**不得**在任何文档里声称 EDL/草稿已包含限幅。
  依据：`edl_to_draft.py` 的能力边界只有恒定 `volume`，无 limiter、无增益自动化。
- **反例**：写「音频已处理完成，可直接发布」——源素材 true peak +0.8 dBFS 仍会原样进入成片。
- **来源**：`[t1]` true peak +0.8 dBFS；`[t2 §5.1]`；`[M]` 工具能力实测。

### AUD-04 · EDL 只能表达恒定音量
- **级别**：P1
- **判定条件**：不得在 EDL 里假设存在音量关键帧/自动化曲线/DSP 链；需要动态处理的内容必须在交付说明里标为"人工步骤"。
- **反例**：在 EDL 的 `reason` 里写「高潮段 +1.5 dB 抬升」却只填了一个恒定 `volume`。
- **来源**：`[M]` `edl_to_draft.py` 只写 `volume`（`VideoSegment/AudioSegment(volume=...)`）。

## 7. EXP —— 交付与导出

### EXP-01 · 同一集出两版，画布与用途固定
- **级别**：P3
- **判定条件**：`canvas` 为 `1920x1080@30`（LS，B站）或 `1080x1920@30`（VT，抖音）；同一集两版的 clips 满足 CUT-03。
- **反例**：给两版做两条不同剪辑；或把 VT 版做成裁切填满。
- **来源**：captain 最终裁决；`format-spec.md §7.1`。

### EXP-02 · 竖屏版禁止裁切填满，须按宽度适配居中
- **级别**：P1
- **判定条件**：VT 版画面为 1280x720 素材 → **1080x608**，垂直居中（游戏区 y = 656–1264）；**不得**放大 2.67× 裁切。
- **反例**：裁掉 78% 横向内容填满 9:16 —— 同时失去画质与战术视野 `[t2 §2.2 事实3]`。
- **来源**：`[t2 §2.2 事实4/方案C]`。

### EXP-03 · 人工验收与人工导出必须显式列出
- **级别**：P0（**不得假装自动化**）
- **判定条件**：交付说明包含以下人工项，一项不漏：①VT 画面按宽度适配（1080x608 居中）；②VT 上下信息区各 656 px 且中部无字；③LS 与 VT 的 clip 时间线一致；④音频限幅已施加；⑤字幕手机端可读；⑥**导出必须人工点击**（剪映 7+ 无自动导出）。
- **反例**：声称"已自动生成成片"或"可直接发布"。
- **来源**：`[environment.md 限制二/限制四]`。

### EXP-04 · 素材描述必须如实区分 CFR/VFR，禁止帧号算术与帧级精确声称
- **级别**：P0（**诚实性规则**）
- **判定条件**：所有文档中：①`a` 描述为 CFR 30fps、`b`/`c` 描述为 **VFR**；②**不出现**「第 N 帧 = N ÷ 30」式算术或"切点在第 N 帧"；③**不出现**"帧级精确卡点"类表述；④上界统一表述为「MediaInfo Video 轨 duration，**比真实内容末点保守约一帧**」，不写"精确末帧"。
- **反例**：写「三段均 720p30 CFR」「切点精确落在第 186 帧」「已实现帧级对齐」。
- **来源**：creative-reviewer 的 `ffmpeg -vf showinfo` 逐帧 PTS 实测（`format-spec.md §2.2`）。
