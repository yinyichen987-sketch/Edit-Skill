# 转场（transitions）

**定位**：把"两个镜头之间怎么接"这件事写清楚 —— 每一条都是**某个教程里屏幕上演过的做法**，
带上剪映的菜单路径、画面上真读到的参数、以及**实测出来的时长**。
本文件不推荐"该不该用转场"，只记录"怎么做"和"教程说了什么时候用"。

> 证据等级见 `README.md`：**L1** = 本机逐帧/逐像素实测；**L2** = 从教程抽帧读出的剪映 UI；
> **L3** = 二手；**L4** = 本项目策略。
> 本轮所有 L2 均来自 `参考视频/教学/` 的抽帧，文件名与时间戳逐条写在表里。
> **凡是我没在画面上看见的数字，一律进 §4「未能验证」。**

## 3. 坑与注意

1. **"转场"有两种完全不同的解法，教程里是分开演的。**
   - `BV1zz4y1N7Dp` 走的是**剪映内置转场库**：顶部 `转场` 页签 → 分类 → 缩略图 → 右侧 **时长** 滑轨。
   - `BV1LguyzoEbz` **完全没提转场库**，它把"转场"当成**两条轨道叠起来 + 关键帧/混合模式/蒙版**来做。
   ⇒ 引用"剪映怎么加转场"时，必须说清是哪一条路。二者**不通用**。

2. **"加了转场"和"看不出切点"是两回事。**
   `BV1fEbK6xEaP` 这条高价值的瓦片**一个转场库效果都没有用**（逐帧扫描只有 10 处大跳变，其中 3 处是黑场、1 处是过曝白闪），
   它的"顺"来自**硬切 + 黑场吸一下 + 卡点**。把它当成"转场教学"会被误导。

3. **黑场的三档时长差了一个数量级。** 同一片里同时存在 **33 ms**、**167 ms**、**667 ms** 三档，
   而且是**看用途分档**：33 ms 只够"藏一个切点"（单帧眨眼），667 ms 已经能被观众**明确读成"黑了一下"**（用于换段落/收尾）。
   ⇒ 想要"隐形"就取 1 帧；想要"断开"就取 0.5 s 量级。

4. **`BV1LguyzoEbz` 的后半段（t≈66s 之后）逐帧黑场检测不可用。**
   这条教程是在手机剪映里录的，**深色 UI 面板本身就占画面 90% 以上的 <16 灰阶像素**（实测 t=32.7–34.7s、
   t=66.2s 起大量帧 `frac<16 ≈ 0.95`）。这些"黑"是**左侧素材库的深灰底**，不是黑场。
   ⇒ 在 UI 录屏里做黑场检测必须排除面板区域，否则全是假阳性。

5. **"0.5 秒"是这个 UP主嫌长的值，不是推荐值。** 原话是"是 0.5 可能比较长"。
   别把 0.5 s 当成"标准转场时长"引用。

6. **教程里演示的转场是加在 `双人同框素材.mp4` / `风声.The.Message.2020…` 这类真人素材上的**，
   不是游戏画面。搬到瓦片素材上是否成立，**本轮没有验证**。
