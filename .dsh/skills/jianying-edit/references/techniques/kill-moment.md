# 击杀瞬间的处理（kill moment）

**这是瓦洛兰特/无畏契约剪辑的核心手法。** 30 秒的成片里，观众记住的就是击杀那一两秒。

> 本文件不是凭空写的：每条都标了证据等级（见 `README.md`），
> 原始报告在 `projects/game-001/research/kill-moment-report.md`（含 11 条"未能验证"清单）。

---

## 1. 手法表

| 手法 | 长什么样 | 什么时候用 | 参数/时长 | 等级与来源 |
|---|---|---|---|---|
| **曲线变速 / 闪进** | 击杀前减速、击杀瞬间回正常或加速 | **几乎每个击杀都用**，本类目的看家手法 | 面板：**画面 → 变速 → 曲线变速**；预设：蒙太奇 / 英雄时刻 / 子弹时间 / 跳接 / **闪进** / 闪出。瓦的击杀慢放用 **闪进**，倍率 **0.1×**（4 个独立教程一致） | **L2** `BV1FJeRzZEtY` t≈42s；⚠️ 部分版本把**变速**做成顶级标签页（画面｜变速｜动画｜调节｜AI效果） |
| **定格** | 击杀帧完全静止，再恢复运动 | 强调某个决定性瞬间 | 剪映**默认 3 秒**，必须手动缩短。真实成片测得重复帧段中位 **216ms**、IQR 119–326ms | **L2** 默认 3s 读自画面；**L1** `killmoment2.json` ⚠️ **是上界，不是编辑时长**（见 §3） |
| **闪白** | 一到几帧全白，压在切点/击杀上 | 藏切点、给击杀一记重拳 | 实测中位 **50–167ms**，最常见 **33 / 67 / 133ms**（1/2/4 帧 @30fps） | **L1** `killmoment2.json`；**L2** 做法 = **媒体 → 官方素材 → 白场**（是**素材**，不是调亮度） |
| **黑场** | 极短近黑 | 分隔节拍、重置注意力 | 实测 **33–600ms** | **L1**；**L2** 媒体 → 官方素材 → **黑场** |
| **抖动 / 震动** | 冲击瞬间画面一震 | 击杀/重击反馈 | 效果名：回弹摇摆、左右晃动、晃动模糊、缩放震荡、摇晃黑、旋转黑、瞬间模糊、抖动模糊、震动闪烁、暗角、跟随运镜。参数：**速度 / 大小**。教程里有明确配方：**特效 → 画面特效 → 搜「交叉闪震」** | **L2** `BV1FJeRzZEtY` t≈54s、`BV1G1r6BuEsF` |
| **击杀卡片** | 击杀帧复制一份、做蒙版、内嵌展示 | 单独突出一次击杀 | 复制片段 → **画面 → 蒙版**（线性/镜面/圆形/矩形/爱心/星形）+ 羽化/圆角；变速 **0.1×** | **L2** `BV1HVe8zRE5m` |
| **曝光 / 发光** | 击杀帧整体提亮、泛光 | 击杀冲击、"clutch" 感 | 调节 → 基础｜HSL｜曲线｜色轮｜蒙版 → 亮度/对比度/高光/阴影/光感。发光默认 **强度40 / 滤镜20 / 光束角度40** | **L2** `BV11hdSYcENH` |

### 标准 vs 进阶（判据：两条高播放短剪辑里都出现了才算标准）

- **标准**：硬切 + 曲线变速（闪进）进击杀；**切点对齐枪口火光**（见 §2）。
- **进阶/非普遍**：真正逐帧的定格、蒙版击杀卡片、曝光泛光、震动合成（交叉闪震）、黑场。
  这些在**部分**高播放片里出现，**不是全部**。

## 2. ★ 最容易搞错的一条：对齐**枪口火光**，不是击杀播报

击杀播报（右上角 feed / 底部横幅）**比实际开火晚 ≈0.2–0.5 秒**。
把切点对齐播报，画面就会"慢半拍"。

- 正确参照物：**橙色枪口火光**（开火那一帧）。
- 本项目对应做法：EDL 取景前置 `PRE = 0.6s`。
- 等级：**L4/L3** —— 来自本项目 `build_by_exclusion.py` L24–29（它引用了一篇 Rocklan 的 AE 教程，
  **该 URL 本轮没有复核**）。这条**值得重新实测确认**。

> 这条与 `kill-extraction.md` 的发现互相印证：击杀横幅本身的位置/时机都不像想象中那样可用。

|---|---|---|---|---|

| Q2 | 仅两条高播放短剪辑 | 中位 **167–170ms** ≈ **5 帧 @30fps**，范围 100–600ms | L1 | 中 |

| Q4 | 击杀慢放倍率 | **0.1×** | L2，4 个独立教程 | 高 |
| Q5 | 闪白时长 | 中位 50–167ms；最常见 33/67/133ms | L1 | 高（"会以这些长度出现"） |
| Q6 | 黑场时长 | 33–600ms | L1 | 中 |
| Q7 | 击杀播报滞后于开火 | ≈0.2–0.5s | L4/L3 | 中（继承，未重测） |
| Q9 | 重复帧出现率 | 14.8–36.5 / 分钟 | L1 | 低（同上界问题） |

### ⚠️ 定格数字为什么只能当上界

判据是"相邻帧完全相同"，但它**同样会命中素材本身就是静止画面的时刻**。
已目视确认一例：`BV1U1kJBrEd7` @7.97–8.60s 是**观战视角拍一个不动的角色**，不是剪辑师的定格。
本项目 `tools/measure_kill_edit.py` 里记录着同一个未解决问题。

**2026-09-13 又发现第二种失效场景（同一条判据）**：对**教程视频**跑同一套判据会得到荒谬结果 ——

| 视频 | 类型 | 严格"定格"段数 | 中位 | 最长 |
|---|---|---|---|---|
| `BV1fEbK6xEaP` | 瓦成片（真剪辑） | 4 | 650ms | **10000ms** |
| `BV1zz4y1N7Dp` | 剪映教程（**录屏**） | **579 段 / 4715 帧（12%）** | 100ms | 2267ms |
| `BV1LguyzoEbz` | 剪映教程（**录屏**） | 122 | 117ms | 1300ms |
| `BV1EahSzYEc8` | 抖音卡点教程 | 0 | — | — |

**原因**：教程是**剪映界面的录屏**，界面大部分时间是静止的 ⇒ 满屏"定格"。
10000ms 的"定格"显然是静止画面/图卡，不是手法。

> **结论（写进方法约定）**：
> ① **L1 效果时长只能在"成片"上量，不能在教程录屏上量。**
> ② 任何"重复帧"结果**必须看最长值**——超过 ~2 秒的一律是静止画面，不是定格。
> ③ 要引用时长，优先引用"白闪 33ms（1 帧）"这一档：1 帧的白闪不可能来自素材本身。

## 4. 明确**不可用**的数字（有人当成"业内常识"在传）

以下三个数字**找不到任何来源**，**不许写进任何规则**：

- 「闪白 0.1 秒」
- 「cut 后 3 帧」
- 「变速 0.5 秒前开始」

最接近的真实数据是**倍率 0.1×**，不是时长。同理，流传的菜单路径
「媒体→素材→画面→基础→定格」**是错的** —— 定格在剪映里是**纯图标工具栏按钮**，没有文字菜单路径。
