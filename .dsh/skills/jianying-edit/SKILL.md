# 剪映剪辑 Skill

## 使命

把原始素材变成**可验收的剪辑决策**，并落成剪映能直接打开的草稿工程。

本 skill 不追求「全自动出片」。剪映 7+ 无法自动导出，**导出必须由人完成**。
定位是「自动生成粗剪草稿 + 可解释的决策记录」。

## 不可妥协的优先级

规则冲突时，永远按此顺序取舍：

1. **故事完整性** —— 信息不缺、顺序不错
2. **合规与安全** —— 不输出黑帧、爆音、错误比例、缺素材
3. **情绪节拍** —— 关键反应镜头不因追求节奏而被删
4. **对话清晰** —— 人声可懂，BGM 不盖人声
5. 最后才优化节奏与视觉打磨

## 硬约束（先读这个）

- **不要试图读取已有草稿**。剪映 11.x 的草稿是加密的，上游库在合规上不提供解密。
  要了解风格，走「分析成片」路线，见 `references/environment.md`。
- **不要承诺自动导出**。导出是人工步骤。
- **每个片段必须写 `rule_id` 和 `reason`**。没有决策理由的剪辑无法复盘，等于没做。
- 时间一律用**秒（浮点数）**。执行层负责单位转换，别在 EDL 里写微秒。

## 工作流

### 1. 探查素材

先摸清手上有什么，不要凭文件名猜。

```bash
python scripts/analyze_film.py <素材路径> --summary
```

### 2. 反推风格（有参考成片时）

若用户提供了自己剪好的成片，逐条分析，归纳出可观察的规律：

```bash
python scripts/analyze_film.py <成片路径> -o film-001.json --summary
```

关注这些**可量化**的指标，而不是「感觉」：

| 指标 | 能推出的规则 |
|---|---|
| 平均/中位镜头时长 | 节奏档位 |
| 镜头时长分布 | 是否有固定的长短交替结构 |
| 每分钟切点数 | 整体密度 |
| 最短/最长镜头 | 允许的极端值边界 |
| 响度（LUFS） | 音频规范 |

多条成片对比后，把规律写成带 ID 的规则（`HOOK-01`、`CUT-03`…），存到 `references/`。

### 3. 产出 EDL

按 `references/edl-schema.md` 写出剪辑决策 JSON。

**先写决策，再想执行。** 每个片段的 `reason` 写「为什么这么切」，不写「切到这里」。

### 4. 校验（不要跳过）

```bash
python scripts/edl_to_draft.py <edl.json> --dry-run
```

会检查轨道引用、素材存在性、时间字段合法性。**校验不过不要强行生成。**

### 5. 生成草稿

```bash
python scripts/edl_to_draft.py <edl.json> --name "项目名"
```

生成前**完全退出剪映**，避免写入冲突。

### 6. 交付人工审阅

生成后必须告知用户：

- 草稿名和位置
- 在剪映里需要**重启或切换草稿**才会看到（有缓存）
- **导出要手动点**（剪映 7+ 不支持自动导出）
- 本次用到的规则 ID 清单，便于逐条核对

## 需要人工批准的环节

以下决策由 agent 给建议，**由人拍板**，不要自行决定：

- 最终 hook 用哪一条
- 关键情绪镜头是否保留
- 删掉有争议的内容
- 音乐选择
- 标题与结尾 CTA

## 必须人工检查（agent 一律不自行决定）

- 品牌敏感内容
- 事实性剪辑
- 法律/版权相关素材
- 人物身份识别
- 高风险客户内容

## 目录结构

```
.dsh/skills/jianying-edit/
├── SKILL.md
├── references/
│   ├── edl-schema.md      # ★ EDL 决策对象规范（核心协议）
│   ├── environment.md     # 环境与兼容性实测事实、已知陷阱
│   └── editing-rules.md   # 规则库（待素材到位后按真实风格填充）
└── scripts/
    ├── analyze_film.py    # 成片/素材 → 结构分析
    └── edl_to_draft.py    # EDL → 剪映草稿
```

## 运行环境

脚本依赖仓库根目录的 venv：

```bash
.venv/Scripts/python.exe scripts/analyze_film.py ...
```

依赖清单见仓库根目录 `requirements.txt`。
