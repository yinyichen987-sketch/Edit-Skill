## 1. 结论摘要（每条一行）

1. 本仓库现有的「底部击杀横幅 = 洋红描边带 y522~613」**是误读**：那条带子与**准星**重合，
   实测到的洋红其实是**准星命中标记**（会从紫色菱形张开成洋红心形带放射线）。
   → L1，本文件 §2.2 与 `verification/frames/4b0460c4_t14.7/14.833/15.033*`
2. **★ 播报卡是"持续状态"而不是"瞬时事件"**：`b61cc53d` @6.500s 那张绿底 `我` 卡
   **在洋红特效之前就已经完整在场**。⇒ 用"卡片出现"当击杀帧，会把**先前**的击杀算到这一刻。
   → L1，§2.1.1（本轮最容易踩的坑）
3. 真正**能机械识别**的击杀 HUD 是观战/回放 HUD 的**播报卡**：一行为
   `[迷你英雄头像][窄色条+击杀者名][高亮竖条][白色武器剪影][十字图标][被击杀者名牌(队伍色)]`。
   → L1 目视确认 + L1 模板匹配命中，§2.1
4. 播报卡在**同一素材里 x 位置会变**（`4b0460c4` 武器剪影 x≈1030~1160；
   `b61cc53d` x≈780~900）⇒ **固定坐标的标定不可能通用**。→ L1，§2.1 与 §4
5. 击杀者视角附带的**文字播报**（如 `击败爆能器携带者`，红底白字、**画面左侧**）
   是比卡片更干净的判据（带文字的独立色块，不是细剪影）。→ L2/L1 目视，§2.3
6. **本机 29 秒原素材里实测到的播报卡区块边界**（模板匹配，阈值 NCC≥0.6）落在
   `10.33 / 10.80 / 16.00 / 17.27 s`；其中 `10.333~11.400` 是**一段连续存在的卡片**。
   → L1，§3（读法见结论 2，**不要**当成击杀时刻）
7. 与既有清单对不上：`analysis2/kills_mine.json` 对 `b61cc53d` 给的是
   `6.2 / 6.8 / 9.567 / 10.7 / 11.767 / …`；并行产出的 `kills_groundtruth.json` 给 F322=10.733。
   本文件的模板进入沿是 **F309~310 = 10.333s**（早 ≈0.40s）。**三者互不一致，本轮不做仲裁。**
   → L1/L4，§2.1.2
8. **A 节的「滞后多少毫秒」查不到**：没有任何可引用的公开数字。
   仓库里唯一的 `≈0.2–0.5 s`（`kill-moment.md` §2 / Q7）是 **L4 继承值**，其原始依据
   （Rocklan 的 AE 教程）**本轮依然无法复核 URL**。→ §3、§4
9. **B 节的「剪辑师公认对齐哪一帧」查不到**：YouTube/Reddit 不可达，B站 搜索被 ban，
   Firecrawl 只回标题级摘要 ⇒ 无法证明任何"共识"。→ §4
10. **C 节**：一次多杀里卡片**不合并**（两张不同玩家的卡同时在列，各自独立一行）→ 支持"各出现一次"；
    但**间隔毫秒数未能测出**。**D 节**：搜到 4 个疑似开源项目 + 1 篇论文，
    **源码/正文全部取不到**（GitHub 与 arXiv 超时）⇒ 只能给 **L3（搜索摘要级）**。→ §2.4、§3、§4

## 2. 判据清单

### A. 画面里哪些 HUD 元素是可靠信号

#### 2.1 右上/右侧的播报卡条（本文件认定为**最可靠**的机械判据）

**长什么样（L1，目视）**。`verification/frames/` 下这几张原图可直接复核：

| 帧 | 裁框 | 看到什么 |
|---|---|---|
| `4b0460c4_t12.500.png`（整帧） | — | 顶部右侧一条绿色卡：`[金色描边迷你头像][窄绿条 我][白色步枪剪影][十字图标][红底白字 ZG0907][头像]` |
| `b61cc53d_t11.000_640x96_640_8_k3.png` | x640 y8 640x96 ×3 | 两条卡叠放；上行红底 `风说想你`→`大白菜`，下行绿底 `我`→`小耳朵` |
| `b61cc53d_t13.900_700x120_560_60_k3.png` | x560 y60 700x120 ×3 | 左：红底白字 `击败爆能器携带者`；右上：两张卡（红行 + 绿行，绿行有**亮黄描边**=最新条目） |

- **队伍色语义**：绿底 = 我方击杀，红底 = 敌方击杀。→ L2（读自画面配色，非官方说明）
- **最新条目会加亮黄描边**（`b61cc53d` @11.0 / @13.9 的绿行）。→ L2
- **位置会变**：`4b0460c4` @12.5 的卡在屏幕最右上（y≈55~105）；
  `b61cc53d` @13.9 的卡在 y≈70~130 且 x 更靠左。⇒ **同一素材内也不固定**。→ L1

**这类判据的好处**：它带**白色武器剪影**这个高对比、形状稳定的要素，
所以可以用**模板匹配**而不是颜色阈值来找（我实现了 `tools/tm_scan.py`）。
`4b0460c4@10.8s` 抠出的武器剪影模板，在 `b61cc53d` 全片上跑 NCC，得到 7 段命中，
峰值 0.704（模板自身在 `b61cc53d` 上是**跨素材**匹配，说明这个形状够稳定）。→ L1

##### ⚠️ 2.1.1 卡片是**事件驱动**的：它出现 ≠ 此刻发生击杀（本轮新发现，很重要）

`b61cc53d` @**6.500s** 的裁图（`…_640x120_560_50_k3.png`）里，**绿底 `我` 卡已经完整在场**
（亮黄描边 = 最新条目）；@6.600s 同一张卡**仍在**，只是整屏被洋红特效淹没。
而 @11.000 的那张绿卡、@13.9 的两张卡，也都是一直挂着的。

⇒ **「播报卡在场」是一个持续状态，不是一次瞬时事件。**
因此：**模板匹配只能得到"卡片区块出现/消失"的边界，不能得到"这条卡是第几条、何时新增"**。
要得到"新增了哪一条"，必须做**逐行跟踪**（跟踪每张卡的位置与内容），本轮**没有做**。
本报告 §3 里的"卡片出现时刻"必须这样读：**那是卡片区块开始出现/消失的时刻**，
不是"这一刻发生了击杀"。→ L1

##### 2.1.2 与并行 ground-truth 的一处**不一致**（供交叉核对，非定论）

`projects/game-001/analysis2/kills_groundtruth.json`（**另一路并行产出**，非本文件作者所写）
把 `b61cc53d` 的 **F322 = 10.733s** 列为候选（confidence=medium）。
本文件的模板响应曲线（`verification/tm_scan/b61cc53d_0.00-29.00_tmpl1030_96.json`）显示：

```
10.300  0.455   ← 基线
10.333  0.619   ← 台阶（+0.16）
10.367  0.704   ← 峰值
… 持续 0.65~0.67 直到 …
11.400  0.660
11.433  0.539   ← 台阶回落
```

⇒ 卡片区块的**进入沿在 F309~310（10.333s）**，比 F322 早 **12~13 帧（≈0.40s）**。
两者不矛盾（F322 落在该卡片区间内部），但**语义不同**：
本方法给的是"卡片区块开始存在"，F322 给的是"HUD 帧间差突变"。
**哪个更接近真实击杀，本文件不下结论**（缺独立真值）。→ L1

**它相对真实击杀是滞后还是精确 —— 查不到**。理由见 §3 的方法学限制：
我手上只有「音频瞬态」和「HUD 自身各要素」两个通道，**没有任何第三方真值**，
所以能测的只有「HUD 各要素彼此的先后」，**不能**测「HUD 相对真实击杀的绝对延迟」。

#### 2.2 画面中部偏下的「洋红/紫色描边 + 被击杀者 ID + 武器图标」——**本轮判为误认**

**结论：那不是击杀横幅，是准星命中标记。** L1，目视证据链：

| 帧（`4b0460c4`） | 裁框 | 看到什么 |
|---|---|---|
| t=14.400 | x320 y505 640x110 ×2 | 只有一枚**紫色菱形描边**（未命中态准星） |
| t=14.700 | 同上 | 准星**张开**成紫色外环 + 内部红色裂块 + 两侧紫色侧翼 + 下方 `E` 键位提示 |
| t=14.833 | x0 y360 1280x360 | 同上，**更亮更满**（命中态）；另见 y≈590 左侧聊天/播报文字行 |
| t=15.033 | 同上 | 同上，开始收束 |
| t=15.200 | x330 y490 380x120 ×2 | 已回落到近似未命中态 |

- 该结构在 `b61cc53d` 的 `t=6.567`（一整屏洋红技能）与 `t=11.000` 也出现，**形状完全一致**。
- **它的中心就在画面正中**（x≈640, y≈565），而 `kill-extraction.md` 标的横幅带是
  `y 522~613 / x 380~900` —— **与准星完全重叠**。
  ⇒ 旧判据在「底部带」上测到的洋红（`4b0460c4` 14.53~15.53 的 0.017~0.037）
  **很可能主要是准星命中标记**，不是横幅。
- 因此：**「洋红占比」既会命中技能光效（`b61cc53d` 6.567 是一整屏洋红），
  又会命中准星命中标记** ⇒ 它不能单独当击杀判据。→ L1
- 「被击杀者 ID + 武器图标」这个描述，在本轮 11 条素材里，**我只在播报卡行里看到**（§2.1），
  没有在画面中部看到同构的元素。→ L1（**这条是"没有看到"，不是"不存在"**）

- **所以本报告对 A 节的总回答是**：**「我击杀了敌人」最可靠的机械标志是播报卡区块的
  进入沿 / 新增行的出现**（L1 可达），但**它只能证明"有一条播报"，不能证明"这一刻发生的"**；
  而**"它相对真实击杀滞后还是精确"，本轮无法用任何来源或实测回答**（见 §3、§4）。

#### 2.3 屏幕顶部中间的敌人头像条

- 结构：`[比分/计时]` 左右各一串 `[迷你英雄头像 + 头像下窄血条]`（L1，`b61cc53d_t10.200` /
  `t11.400` 的 x700 y8 260x60 ×4 裁图）。
- **但本轮没能拿到可信的"存活 vs 阵亡"视觉差别**：
  在有击杀的窗口里（`b61cc53d` 10.2 → 11.4），**头像数量与灰度在裁图上肉眼看不出变化**；
  头像下方的窄条在两张裁图里**都接近空**（若它是血条，则它不表达"存活"）。
  → **未能确认**。我**不写**"阵亡会变灰/加叉"这类说法，因为我没有在本机画面上看到实例。
- 上一轮的 v1/v2/v3 尝试（`docs/lessons.md` 第 6 轮 §2）也全部失败：
  v1 全局亮度阈值被受击态（血条变红）污染；v2 逐头像归一化被 HUD 渐变底吃掉；
  v3 饱和度（存活≈54 / 阵亡≈14）分离明显但受击/治疗仍抖。→ L1，**已有失败记录**。

#### 2.4 底部 HUD 的其它变化（经济 / 技能栏 / 弹匣）会不会被误当击杀

**会。** 直接证据：`kill-extraction.md` §2 已记录 `4b0460c4` 的 `16.733s`
**是战术计分板/回合结算浮层弹出**，被旧判据当成击杀（带内洋红 0.0000、高频 0.34）。
本轮我再确认了该判据的物理原因：底部带=通用 HUD，弹匣数字（20→24→30）、
技能图标、经济都在变。→ L1（既有）+ L2（我本轮看到弹匣/经济在动）

另外本轮新看到一类**同构的假信号**：左下角的
`（广播）… 在A区发现一名敌人` 文字行（`4b0460c4` @14.833、`b61cc53d` @8.500）
是**地图标记播报**，和击杀无关，但它同样会点亮"底部文字带"。→ L2

#### 2.5 击杀音效（audio transient）是不是更早/更准的锚点

**本轮能给的只有"数值上是全片最尖的起音"这件事，而不是"更早/更准"。** L1：

| 素材 | 窗口 | 全片最强起音 | 相邻队手 HUD |
|---|---|---|---|
| `4b0460c4` | 13.2~17.6s | **14.830s onset=0.1899**（同窗其余峰值 ≤0.1127） | 播报卡命中段正好落在 **14.833** |
| `b61cc53d` | 10.0~11.6s | 起音峰值出现在 **10.855 / 11.085** 之后 | 但卡片在 **10.333** 就已存在 |

- `4b0460c4` 这一例：**最强音频起音与播报卡出现同帧**（相差 ≤1 帧 / 33ms）。→ L1
- `b61cc53d` 这一例：**卡片比音频起音早 ≈0.52s** ⇒ **音频不是更早的锚点**（至少不是总成立）。→ L1
- **不能说**"音频比播报早"或"音频更准"：我没有独立真值，而且上表两例就互相矛盾。

### C. 多杀：播报与横幅是各出现一次还是合并

- **不合并，各占一行**（L1，目视）：`b61cc53d` @11.000 与 @13.900 的两张卡里，
  可见**两张不同玩家的卡同时存在**（红行 `风说想你`，绿行 `我`），每张卡自带
  击杀者、武器、被击杀者 ⇒ 是**独立条目**，不是合并成一条"2 KILLS"。
- **间隔毫秒数：未能验证**。我没有标注出一次对枪里的 2/3 连杀逐帧序列。
- 唯一与多杀有关的本地数字是 `b61cc53d` 的卡片存在时长：
  `10.333~11.400`（**约 1.07s**，模板匹配连续命中段）——这是**卡片滞留时长**，
  **不是**两次击杀的间隔，不要混用。→ L1
