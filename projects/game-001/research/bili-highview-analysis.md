## 一、结构实测

| 画幅 | **1920x1080 横** | 480x852 **竖**（重传稿） | **1920x1080 横** | 1920x1080 横 |

| **切点密度** | **38.45 切/分** | 29.02 | 20.27 | **12 切/分** |
| 最短 / 最长镜 | 0.267s / 7.433s | — | 0.8s / **11.3s** | 0.94s / 12.19s |

| 字幕 | **无**（只有游戏自带 UI） | 无 | 无 | 无 ✓ |

### 靠得住的几条结论

1. **画幅以横屏 16:9 为主**（3 条里 2 条横屏；那条竖屏是 480x852 的低清重传稿）。
   ⇒ 我们做 B站横屏版是对的。
2. **全程没有字幕/解说**。画面里只有游戏自身的 HUD 与横幅（如「败北」）。
   ⇒ 用户要求"把所有文字解说部分删除"**与高播放样本一致**。
3. **切点密度 20–38 切/分，中位镜长 1.0–2.7 秒**。
   而我 v4 是 **12 切/分、均长 4.42s** —— **慢了 2–3 倍**。
4. **两条横屏都以长镜收尾**：#1 末镜 7.4s、#3 末镜 **11.3s**。
   与调研里"结尾要 hold 住"一致，也和"stillness makes density land"同源。
5. **内容类型差异很大**：三支的看点完全不同 ——
   - #1 = **33 个短促瞬间的快混剪**（刀/枪检视、技能特效、对枪、击杀、败北横幅…）
   - #3 = **皮肤/技能特效展示**（粉白技能特效、角色模型、检视），不是击杀集锦
   说明**高播放不等于某一种固定剪法；但共性是没有一个字幕、画面变化非常密**。

## 二、⚠️ 一个必须说清的**冲突**

用户此前的要求是："集锦就是**保证每个原始素材先后一致**而**不要把片段切割太碎**"。
我按这个做成了 **7 镜 / 均长 4.42s / 12 切每分**。

但**实测的高播放样本恰好相反**：它们用 **11–33 个镜头、20–38 切每分**，
素材是"很多个不同的瞬间"而不是"三段长素材"。

根因不在手法，在**素材量**：#1 是 33 个不同回合/场景拼起来的，
而**我们只有 3 段共 70 秒**的素材，其中项目分析判为"有战斗信息"的高光只有 19.5 秒。

也就是说，**"每段素材一整段连续"与"20–38 切/分的快混剪"在现有素材下互斥** ——
要快切就必须把 70 秒切成很多 1 秒左右的小段（用户说的"割裂"），
要"不割裂"就只能像现在这样每段用一条长镜。

### 三条可选路线（需要用户定）

- **A. 维持现版（尊重"先后一致/不切碎"）**：7 镜 / 12 切每分。
  与高播放样本的节奏差距最大，但完全符合用户此前给的定义。
- **B. 靠拢样本（快混剪）**：把 70 秒**全部**当素材池（不只 19.5s 高光），
  切成 ~30 个 1–2s 的小段，按素材内部**时间顺序**遍历（不跳来跳去），
  做到 20–30 切/分。**仍然每条素材内部有序**，只是每段取的不是一整段而是连续推进中的一小截。
  这是我认为**最可能提升播放表现**的一版。
- **C. 折中**：把 3 段各切成 3–4 个 2–3s 的连续小块（共 10–12 镜 / 约 20 切每分），
  素材内部仍按顺序、块与块之间不重叠。

> 注意 B 与用户的"不要切割太碎"是**直接冲突**的 ——
> 所以这一条**必须由用户拍板**，我不擅自改。

## 三、顺带得到的工程结论

- **高播放样本的响度差异极大**（−7.9 / −17.4 / −22.4 LUFS），
  说明"响度"不是播放量的决定因素；但 #1 那条 −7.9 LUFS 且**真峰值 +1.4 dBFS（已经削顶）**
  说明**平台会替它兜住**，不必为了"不削顶"把自己压得过轻。
  我们现在的 −15.0 LUFS / −2.2 dBFS 属于保守但安全的位置。
- 那条 42.2 万的是 **480x852 / 26.418fps** 的**重传稿** ——
  高播放并不要求高分辨率/标准帧率。**内容与节奏比画质重要。**
