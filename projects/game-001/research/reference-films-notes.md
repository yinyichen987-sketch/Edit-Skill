# 用户参考成片实测（`瓦参考素材/`）

用户把两个模板从剪映导出了成片放进工作区。**这是正确的学习路径** ——
之前试图读草稿失败（`draft_content.json` 是密文，详见 `template-drafts-audit.md`），
而成片是开放的，可以直接量。

## 一、基本参数（`pymediainfo`）

| 文件 | 时长 | 分辨率 | 帧率 | 视频码率 | 音频 |
|---|---|---|---|---|---|
| `9月12日.mp4` | 37.222s | **1920x1080 (16:9)** | 30fps **CFR** | 8,215 kbps | AAC 2ch 44.1kHz 198kbps |
| `9月12日 (1).mp4` | 43.468s | **1920x1080 (16:9)** | 30fps **CFR** | 6,372 kbps | AAC 2ch 44.1kHz 192kbps |

⇒ 两份都是**横屏 16:9、30fps、剪映导出**（44.1kHz AAC 是剪映默认）。

## 二、切点与节奏（`analyze_film.py` + 自写帧差检测）

`analyze_film.py` 用 luma 场景分数，在 VALORANT 这类连续运动的画面上会**欠检**；
自写的 10fps 灰度帧差（阈值 = 均值 + 3σ）更贴近实际：

| 文件 | 检测到的切点（秒） | 镜头结构 |
|---|---|---|
| `9月12日.mp4` | 0.2 / 0.9 / **23.3** / **36.7** | 4 镜：0.7s 片头 + **22.4s** + **13.4s** + 0.5s 尾 |
| `9月12日 (1).mp4` | 0.2 / 0.9 / **31.7** / **43.0** | 4 镜：0.7s 片头 + **30.8s** + **11.3s** + 0.5s 尾 |

**这是本文件最重要的一条**：参考成片的镜头是 **11–31 秒**量级，
平均 9.3s / 14.5s，切点密度仅 **4.84 / 2.76 切/分钟**。
⇒ 用户的"**切割得太割裂**"不是随口说的：他心里的参照是**极慢的长镜展示**，
而我第 1 版做的是 56 切/分的快剪，第 2 版 32，第 3 版 16 —— 方向对，但离参照仍远。

**未检出任何转场** —— 只有硬切。（这与"转场要高级"并不矛盾：参考里根本不用转场。）

  ⇒ **满屏 16:9**，不是加边也不是模糊底。

  - 文案 "购买阶段" / "王牌精锐"，**在上部居中**，字框中心约 **y≈200px**
    （= 画布高的 **18.5%**）
  - 字号约 **48–60px**（4.4–5.5% 画布高），**白色粗体**
  - **字下有半透明底板**（玻璃感面板），宽度比文字宽出不少
  - 底板下方还有一行**小字副标题**（"按 [B] 购买" / "Lucky"），约 20px
  - 右上角另有一个**小数据面板**（"射速误差 0.20 / 0.00"）

  ⇒ 这两份是**剪映免费模板的未填充占位稿**（用户没把自己的素材填进去），

## 四、声音（`ebur128` + 逐秒 RMS/过零率）

| 文件 | 整片响度 | 真峰值 | 逐秒 RMS | 过零率 |
|---|---|---|---|---|
| `9月12日.mp4` | **−10.1 LUFS** | +0.3 dBFS | 稳定 −8 ~ −9 dBFS，无起伏 | 0.08–0.18（低） |
| `9月12日 (1).mp4` | **−8.3 LUFS** | −0.1 dBFS | 稳定 −7 ~ −11 dBFS | 0.10–0.24（低） |

**读法**：RMS 全程平稳、过零率低 ⇒ **只有一条持续的音乐床，没有游戏原声的动态**。

## 六、一个需要用户拍板的矛盾

参考成片是**武器/手套展示（inspect）慢剪**：两三个 11–31 秒的长镜、只有一条音乐床、
无转场。而用户要的是"**把这几个连接起来做成一个游戏集锦**" —— 集锦天然需要多个高光，
而高光素材本身是碎片化的（本项目素材分析：可用高光中位 **1.0s**、最长连续段 **3.4s**）。

两者可以调和，但方向必须由用户选：

- **A. 靠拢参照（慢剪展示）**：镜头拉到 5–8s，只保留 3 个镜头，全片可能只有 2–3 个"事件"。
  素材能支撑（c 段 6.4→11.1、a 段 5.6→9.4、b 段 5.4→9.2 都是连续可用的），
  但那样的成片**不是集锦，是慢剪 vlog**。
- **B. 保持集锦（现版）**：5 镜 / 均长 3.0s / 16 切每分，已比前两版大幅放缓。
- **C. 折中**：3 镜，各 5.0s（`10+11+11 = 32 拍` 仍能整除到 15.000s）。

现在交付的是 **B**，并已把参考成片的**排版/构图/响度**口径吸收进来。

## 七、B站 高播放量无畏契约剪辑的**时长分布**（实测，2026-09-12）

用户要求"去 B站 搜播放量高的剪辑视频，识别并提取手法"。

### 先说清楚能做到什么、做不到什么

- **能做到**：抓页面**元数据** —— 标题、UP主、**时长**、播放量、标签。
- **做不到**：**看不了视频画面**。`read_page` 走的是 Firecrawl 的云端 JS 渲染，
  返回的是播放器外壳 + 推荐位列表，**没有任何帧/时间轴信息**。
  （B站的 AI 字幕也拿不到：页面显示"暂无字幕"。）
- ⇒ 要真正提取**剪辑手法**（镜头长度、切点、转场、变速、字幕节奏），
  必须拿到**视频文件**，像 `瓦参考素材/` 那样放进工作区，再用
  `scripts/analyze_film.py` 量。**页面抓取替代不了对成片的测量。**

### 拿到手的硬数据：时长与播放量

从高播放视频的推荐位里实录（`时长 / 播放量`）：

| 视频 | 时长 | 播放量 |
|---|---|---|
| 花200找大学生剪的，他说包燃的 | **00:50** | **57.7 万** |
| 你再刀我试试呢4.0 | **00:38** | **42.2 万** |
| 练枪不如烧香 | **00:30** | **40.3 万** |
| 两个人吗？一发就够了！ | 00:35 | 14.3 万 |
| 目前生涯里最离谱的神经枪 | 00:22 | 13.7 万 |
| 看你们打瓦手的准度我都头疼 | 00:23 | 12.1 万 |
| 打不过对面大哥我们就这样 | 00:30 | 10.9 万 |
| 颗秒幻影真t0了 | 00:14 | 8.6 万 |
| 就这个停顿 就这个卡点爽！ | 00:33 | 8.5 万 |
| 瓦-life force | 00:16 | 7.2 万 |
| 【VALORANT/混剪/高燃】质感十足…自制3D建模 | **02:24** | **3.2 万** |
| 【无畏契约剪辑教程】瑞纳抓e转场 | 教程 | 0.24 万 |

**结论（可直接用）**：
1. **高播放集中在 14–50 秒**（中位数约 30 秒）。
2. **精剪长片反而播放低**：那条"历时20多天剪辑 + 自制3D建模"的 2 分 24 秒片子只有 3.2 万，
   而 22–50 秒的短剪辑是 10–57 万。**投入产出严重不成比例。**
3. 标题普遍是**一个具体瞬间或一句吐槽**（"就这个停顿 就这个卡点爽！"、"练枪不如烧香"），
   不是"高燃集锦"这种泛标题 —— 说明**看点在前 1 秒就要可读**。
4. 有一条标题本身就点出了手法：**「就这个停顿」** —— 停顿/留白是被观众认可的技巧
   （与调研里"stillness placed against density"一致）。

### 据此对项目的改动：**取消固定总长**

用户明确说"时长没有硬性要求，不要为了划定死时长而选择奇怪的剪辑手法"。

此前我为了凑 **64 拍 = 16 小节 = 30.000s**（好让自制的 128BPM BGM 正好铺满整小节），
反过来在切素材。现在改成：

- **先按内容决定每镜多长** → 总长 66 拍 = **30.9375s**（把 b 段的「获胜」横幅多留一拍半）；
- **BGM 去适配成片**：`make_bgm.py 17 9` 生成 17 小节（31.875s），
  EDL 按成片总长引用它（段被裁到 30.9375s，末尾 0.25s 淡出）。

即 **剪辑决定时长，BGM 服从剪辑**，方向反过来。
