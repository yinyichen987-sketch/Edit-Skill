# 击杀集锦 B01 · 音效版本对比（whoosh 怎么处理）

**分支**：`kill-frame-training-2`
**起因**：用户听完音频版（`击杀集锦_B01_音频版`）后说 ——

> 「我觉得 whoosh 音效有些太过突兀了，或许添加画面效果会好一些？
> 而且这个音效太过生硬了，特别是每段都切一次，有点坏气氛」

**结论**：他的三条判断**都能被量出来**，而且「每段都切一次」是我选的参数（`--whoosh all`，
第 17 轮当时也给了 `material` 选项）。本轮做了**两个对比版本**：一个把强调收到「只在换素材」，
一个把强调**从听觉换到视觉**。**选哪个由用户定，我不替他拍板。**

---

## 1. ★ 先把「突兀 / 生硬 / 坏气氛」量出来（L1 实测）

| 指标 | 实测值 | 说明 |
|---|---|---|
| whoosh 条数 | **13 条** | = 每个内部切点 1 条 |
| 平均间隔 | **每 2.47s 一次** | 32.167s ÷ 13 |
| 总占时 | **4.55s = 全片 14.1%** | 13 × 0.35s |
| 音色 | 带通噪声，**频谱重心 3643 Hz** | **无调性**的「呲」声 |
| 电平 | 素材峰值 **−1.9 dBFS**，按 0.8 播 ⇒ **−3.8 dBFS** | BGM 峰值 −3.1 × 0.7 = **−6.2 dBFS** |
| | | ⇒ **whoosh 的峰值比 BGM 还高 2.4 dB** |
| 覆盖范围 | 每条 0.35s / 镜头中位 2.2s = **16%** | 不算长，但**次数太多** |

**三条原因叠在一起** ⇒「坏气氛」是它们的合成结果，不是错觉：

1. **次数多**：每 2.5 秒一次，32 秒里 13 次；
2. **音色是宽带噪声**：叠在有调性的 128 BPM 电子 BGM 上，感知上天然「尖」；
3. **电平比 BGM 峰值还高 2.4 dB**：它是全片最"凸"的那一层。

---

## 2. ★ 附带纠正：第 17 轮我对「真峰」的结论说错了

第 17 轮我做过一次实验（把 impact 降 4 dB），据此写了「真峰主要是预览渲染器的 AAC 过采样过冲，
不是哪一层音效顶上去的」。**这个结论不完整** —— 那次实验**没有动 whoosh**，而 whoosh 才是峰值元凶。

| 版本 | whoosh | 真峰 | 响度 |
|---|---|---|---|
| 音频版（第 17 轮） | 13 条 @0.8 | **−0.1 dBFS** ✗ 超口径 | −13.9 LUFS |
| **轻音效版（本轮）** | 4 条 @0.45 | **−2.3 dBFS** ✓ | −14.6 LUFS |
| **闪白版（本轮）** | 0 条 | **−2.4 dBFS** ✓ | −14.7 LUFS |

⇒ 把 whoosh 减到 4 条 / 去掉，**真峰回落 2.2 dB**，**两个新版本都进了项目口径（≈−14 LUFS / ≤−1 dBTP）**。

**正确的结论**：第 17 轮那个 0.9 dB 的超标，**是 whoosh 顶上去的**（宽带噪声 + 峰值 −1.9 dBFS × 0.8）；
「主要是渲染器过采样过冲」这句**推翻**。
（过采样过冲确实存在，但它不是这 2.2 dB 的主因 —— 主因是那一层噪声本身太凸。）

## 3. 两个对比版本

| | **轻音效版** | **闪白版** |
|---|---|---|
| whoosh | **4 条**（只在换素材的接缝）、音量 **0.45** | **0 条** |
| 画面 | 无转场 | **闪白 0.13s × 4 处**（同样只在换素材的接缝） |
| impact | 15 条（落击杀帧）不变 | 15 条（落击杀帧）不变 |
| BGM / 游戏原声 | 不变（0.7 / 0.45） | 不变（0.7 / 0.45） |
| 音频叠加总数 | 20 条 | 16 条 |
| 时长 | 32.167s | 32.167s（EDL 口径，见 §5 的坑） |
| 响度 / 真峰 | −14.6 LUFS / −2.3 dBFS | −14.7 LUFS / −2.4 dBFS |
| 预览片 | `projects/game-001/preview/击杀集锦_B01_轻音效版_preview.mp4` | `projects/game-001/preview/击杀集锦_B01_闪白版_preview.mp4` |
| EDL | `projects/game-001/edl/击杀集锦_B01_轻音效版.json` | `projects/game-001/edl/击杀集锦_B01_闪白版.json` |
| 台账 | `…轻音效版.plan.json` | `…闪白版.plan.json` |

**两个版本改的是同一件事的两个方向**：把「转场强调」从**每个切点（13 次）**收到**只在换素材（4 次）**，
一个用**听觉**表达，一个用**视觉**表达 —— 这样能直接比较「音效 vs 画效」。

**没有生成草稿**：草稿是"定稿产物"，等用户选定方向再出（避免仓库里堆一堆半成品）。

## 4. 闪白在画面里真的出现了（L1 验证）

按 EDL 的 4 个闪白时刻（6.167 / 12.500 / 16.767 / 23.267）抽帧量**画面平均亮度**：

| 相对闪白中心 | −0.20s | −0.03s | 中心 | +0.03s | +0.20s |
|---|---|---|---|---|---|
| 平均亮度 | 132.7 | **255.0** | 181.4 | 181.4 | 108.5 |

⇒ 亮度冲到 **255（纯白）**，持续约 0.13s，位置落在 4 个素材接缝 ✓

**顺带一个读数解释**（不是 bug）：在闪白版上做「场景检测切点 vs EDL 切点」，
**有闪白的那 4 个切点会报早 ~34ms**，其余 9 个全 0ms。
原因：闪白从切点前 65ms 就开始变亮（`fade=in` 从 T−d/2 起），**亮度型检测器会咬到这条亮度斜坡**。
对照验证：**轻音效版 / 音频版（都没有闪白）13 个切点全 0ms** ⇒ 这 34ms 是检测器现象，不是时间轴漂移。

## 5. ★ 走闪白这条路，有两个「我做不到」的坑，必须先说

1. **预览和剪映在转场上不等价**：预览是「白色叠加层 + alpha 包络」，**不改变任何时长**；
   剪映的转场会**占用前后片段的时间** ⇒ **剪映里的成片会比 32.167s 短**（短多少 = 转场时长的累积）。
   ⇒ 走闪白路线的话，**总时长要重新定**，导出后必须复量。EDL 的 `_manual` 里记了这条。
2. **剪映里闪白长什么样、能不能脚本化摆准**：`edl_to_draft.py` 只写**转场名 + 时长**，
   实际观感**要到剪映里看**。本节 §4 那条预览是**近似**，**不能当剪映效果的验收**。

## 6. 本轮改了什么（工具层，可复算）

`projects/game-001/tools/make_killreel_edl.py` 新增两个参数：

```
--transition 闪白                        在切点挂转场（`类型[:时长秒]`，如 `闪白:0.13`）
--transition-scope {all,material,none}   加在哪（默认 material = 只在换素材的接缝）
```

- EDL 语义取自 `references/edl-schema.md`「转场语义」：`transition` 写在片段上
  = **「进入本片段」的转场** ⇒ 从第 2 个片段开始挂（挂第 1 个片段无效）。
- **回归对照**：不给新参数时，重新生成的 EDL 与已提交版本**逐字段相同**；
  台账只多 2 个键（`transition: null` / `transition_scope: "none"`）。
- **校验**：两个新 EDL 都过 `edl_to_draft.py --dry-run`（4 轨 / 14 片段 / 音频叠加 20 与 16 条）。
- 新的 `_manual` 项：转场在剪映里占时长、预览不占 ⇒ 两者不等价。

## 8. 等你选（不是二选一，组合也可以）

| 选项 | 做法 | 代价 / 备注 |
|---|---|---|
| `1` **轻音效版** | whoosh 4 条 @0.45 | 保留一点"甩"的感觉；时长不变 |
| `2` **闪白版** | 无 whoosh + 闪白 ×4 | 你提的画面效果；**剪映成片会变短** |
| `3` **两个都要** | whoosh 4 条 @0.45 **+** 闪白 ×4 | 强调更重；时长同样会变 |
| `4` **更彻底** | whoosh 全去、impact 也去、只留 BGM | 最"干净"，但**击杀没有重音**了 |
| `5` **只调参数** | 例如 whoosh 6 条 @0.35 / 闪白只留 2 处 | 说个数就行 |
| `6` **换 whoosh 音色或裁短** | 0.35s 裁到 0.18s，或换低频的 `sub_drop` | 如果只是嫌「太长太尖」而不是嫌多 |

**我倾向哪个（仅供参考，你定）**：如果按你的原话「每段都切一次有点坏气氛」，
那**问题的一半是次数**，不是"不该有 whoosh" ⇒ `1` 或 `3` 比 `4` 更稳；
但 `2` 是你提的方向，而且它的真峰/响度最漂亮（−2.4 dBFS / −14.7 LUFS）。

**还有一件必须提醒**：走 `2/3` 的话，**剪映里的总时长会变**，
而 32.167s 是你在第 16 轮认可过的时长 ⇒ 需要你重新确认。
